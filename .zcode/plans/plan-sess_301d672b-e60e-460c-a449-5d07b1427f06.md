## 目标

按照 opencode 的权限模型升级 `permission.py`：三级动作（allow / ask / deny）+ 通配符模式匹配 + 按参数粒度记忆批准，规则来源为代码默认规则 + `codeagent.json` 用户配置。

## 核心设计

**规则模型**：每条规则 = `(工具名, 参数模式, 动作)`，动作 ∈ `allow / ask / deny`。用 `fnmatch.fnmatch` 同时匹配工具名和参数模式（如 `run_command` 匹配命令串 `git *`、`write_file` 匹配路径 `*.env`）。求值语义与 opencode 一致：**最后一条匹配的规则生效**，无匹配时默认 `ask`。

**三个规则层**（后层覆盖前层）：
1. 代码内置默认规则：`read_file`/`list_dir` → allow，`write_file`/`edit_file`/`run_command` → ask
2. `codeagent.json` 用户规则（用户规则排在后，可覆盖默认）
3. 会话内"总是允许"积累的规则（选 a 后追加 `(工具, 模式, allow)`，仅本会话有效）

## 实施步骤

### 1. 重写 `src/codeagent/permission.py`
- `Permission` 类持有三层规则表；`check(tool_name, args)` 返回动作
- `evaluate()` 实现 findLast 匹配语义
- deny → 直接返回拒绝（不询问用户）；ask → 交互确认，提示选项改为 `[y]本次允许 / [n]拒绝 / [a]总是允许该模式`
- `-y` 参数（approved_all）保留，全部视为 allow

### 2. 工具注册扩展（`tools/base.py` + 各工具 schema）
- schema 增加可选字段 `pattern_arg`，声明从哪个参数提取权限模式：
  `run_command → "command"`，`write_file`/`edit_file`/`read_file → "path"`
- 未声明 → 模式为 `*`

### 3. 配置加载（`src/codeagent/config.py`）
- 读取工作区根目录 `codeagent.json` 的 `"permissions"` 字段
- 支持两种写法（同 opencode）：字符串简写 `"write_file": "ask"`；对象细分 `"run_command": {"git *": "allow", "rm -rf*": "deny"}`
- 文件不存在/字段缺失 → 仅用默认规则；JSON 解析失败 → 打印警告并降级为默认规则（不崩溃）

### 4. `agent.py` 适配
- `_execute` 调整顺序：先 `json.loads` 解析参数，再 `permission.check(name, args)`（当前是先 check 后解析，拿不到参数）

### 5. 测试

- 更新 `tests/test_agent.py` 适配 `_execute` 新签名
- 全量 pytest 回归
