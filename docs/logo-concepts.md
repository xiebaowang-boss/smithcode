# SmithCode Logo 方案（待选）

主题：**一把锤子在敲**。本文档给出 4 个方向，供选型后再细化（矢量版、欢迎横幅接线）。

## 设计基调

- **现有品牌资产**：主色终端绿 `#23d18b`，点缀炉火琥珀 `#e0af68`（见 `src/smithcode/welcome.py` 的 `banner()`）；叙事是「铁匠铺」——现有问候语为「炉火正旺 / 淬火完成 / 铁砧已就位」。
- **第一身份面是终端**：logo 的默认形态是 ASCII（TUI 完整版 6 行、REPL 单行紧凑版）。图形版（favicon / README / 头像）是第二位。
- **落地约束**：多行版宽度控制在 42 列内、行数尽量 ≤ 8 行（现有 `LOGO_WIDTH = 42`，TUI 在 `width < LOGO_WIDTH + 12` 时降级为紧凑版）；字符只用块元素与制表符（`█ ▀ ▄ ▁ ▔ ▗ ▖ ▝ ▘ ░ ▒ ▓ ╱╲`），与现有 `LOGO` 同族，不引入 emoji / 宽字符。

## 方案 1 · 落锤（经典剪影）

最直白的一版：锤头 + 斜柄 + 铁砧台面 + 迸溅火星，一眼看出「在敲」。

```text
                ╱╱
               ╱╱
              ╱╱
             ╱╱
    ▗██████████████▖
    ████████████████
    ▝██████████████▘
       *   *   *   *
  ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁
  ██████████████████████
      ██████████████
      ██████████████
    ▟████████████████▙
```

- **矢量版**：单色剪影（锤身实心、铁砧实心），火星用琥珀色 3~5 个圆点；45° 斜柄，锤头下沿与砧面留 1~2px 空隙暗示「正要落下」。
- **适用**：README 头图、TUI 欢迎横幅（需压缩行数）、发布公告图。
- **优劣**：辨识度最高、最讨喜；行数偏多（13 行），做终端横幅要裁掉铁砧下半部或改横排。

## 方案 2 · 锤即提示符（极简几何）

把终端提示符 `>` 变成锤柄，方块光标变成锤头，敲击迸出的就是命令的输出。最贴合「终端工具」气质的一版，也最容易缩到 16×16 做 favicon。

```text
   >
    >▗███████▖
     >█████████▖
      ▝▀▀▀▀▀▀▀▀▀
        *   *   *
   ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔
```

- **矢量版**：3 段 45° 阶梯 `>` 构成柄，直角梯形作锤头，底部一条横线作工作台；纯几何、无写实细节，线条粗细一致。
- **适用**：favicon / 应用图标 / 侧边栏 / 头像 —— 小尺寸下唯一还认得出的方案。
- **优劣**：最有现代感、最像「产品」；写实感最弱，需要搭配字标才不歧义。`>` 可换成项目实际提示符字形（如 `❯`），但那类字形宽度不定，终端版建议保留 ASCII。

## 方案 3 · 锻造代码（锤 + 尖括号砧）

锤子敲在 `<———>` 的砧面上：**代码就是被锻造的材料**。寓意最贴合产品本身（不是泛用工具，而是「把代码敲成型」）。

```text
                ╱╱
               ╱╱
        ▗██████████▖
        ████████████
        ▝▀▀▀▀▀▀▀▀▀▀▘
       *   *   *   *
    <━━━━━━━━━━━━━━>
      ████████████
    ▟██████████████▙
```

- **矢量版**：锤头方正（近直角），砧面用一对尖括号 `< >` 内接实线；火星即「编译/运行的火花」，可做成琥珀点。
- **适用**：README 功能配图、文档页头、banner 右侧装饰。
- **优劣**：叙事最强、开发味最足；尖括号在小尺寸下会糊，需简化成纯横线。

## 方案 4 · 炉火铁砧（品牌叙事版）

同一「落锤」构图，下方从铁砧延伸出炉火渐隐（`▓▒░` 由实到虚），直接串起现有问候语的「炉火 / 淬火 / 铁砧」意象；也可收进圆形徽章做发布贴纸与社群头像。

```text
                ╱╱
               ╱╱
        ▗██████████▖
        ████████████
        ▝▀▀▀▀▀▀▀▀▀▀▘
       *   *   *   *
   ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁
   ██████████████████
      ████████████
   ▟██████████████████▙
    ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒
     ░░░░░░░░░░░░░░░░
        ▒▒▒░  ░▒▒▒
```

- **矢量版**：上实下虚——锤与砧为实心剪影，底部炉火用琥珀到透明的渐变弧线；圆章版则加双同心圆环与底部弧光。
- **适用**：发布贴纸、社群头像、启动画面（TUI 首屏可加动画：顶部炉火呼吸）。
- **优劣**：品牌故事最完整、颜色最有辨识度；最复杂，终端版依赖颜色，纯单色下会退化为方案 1。

## 组合与落地建议（选定后执行）

1. **终端形态**做成「图形标 + 现有块字标」横排：左侧放压缩到 6 行的 mark（方案 2 可直接用，方案 1/3/4 需去铁砧），右侧保留现在的 `SMITH` 块字 —— 这样 TUI 横幅不用整体重构，只改 `welcome.py` 的 `LOGO` / `COMPACT` 与 `LOGO_WIDTH`。
2. **图形形态**按选定方案出 SVG（单色版 + 双色版），放 `docs/logo/`，再派生 favicon 与 README 头图。
3. 改动 `welcome.py` 属于用户可见行为，按项目约定同步一条 `CHANGELOG.md` 的 `[未发布]` 条目。

## 下一步需要定的事

- 选哪个方向（或指定「2 的简洁 + 4 的炉火配色」这类组合）。
- 图形标与字标是**横排**还是**上下排**。
- 是否要顺便把 `COMPACT` 单行版加上 mark 前缀（如 `⚒ Smith Code`，注意 emoji 宽度与终端兼容性）。
